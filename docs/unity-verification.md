# Unity 확인 목록

컴파일 게이트는 이 백엔드가 **컴파일된다**는 것만 지킨다. DOTween은 자기 업데이트
루프에서 스스로 진행하므로, 이 어댑터가 실제로 옳게 도는지는 에디터에서만 확인된다.
아래는 손으로 한다.

## 준비

1. `Start` · `Loop` · `End`를 전부 선언한 그래프를 하나 만든다. `Start`는 페이드 인 +
   스케일(가능하면 `OutBack`처럼 오버슈트하는 이징으로), `Loop`는 은은한 `Float`,
   `End`는 페이드 아웃 정도면 충분하다
2. 그 그래프를 꽂은 `MotionPlayer`가 있는 프리팹을 하나 만들고 `MotionDoTweenScope`를
   함께 붙인다
3. 비교 기준을 먼저 잡는다 — **`UIMOTION_DOTWEEN` 없이** 연출을 한 번 돌려 보고
   눈에 익혀 둔다. 아래 항목의 절반은 "내장 러너와 같은가"를 묻는다

## 확인 항목

- [ ] **`UIMOTION_DOTWEEN`이 없으면 패키지가 컴파일에서 빠지고 연출은 그대로 동작한다.**
      콘솔에 오류가 없고 `MotionDoTweenBootstrap`이 코드 완성에도 뜨지 않는다.
      이 상태에서 연출은 내장 러너로 정상적으로 돈다

- [ ] 정의를 추가하고 부트스트랩을 부르면 **연출이 여전히 같은 타이밍으로 돈다.**
      길이나 곡선이 눈에 띄게 달라지면 이징 매핑이나 시간 스케일이 어긋난 것이다.
      오버슈트하는 이징이 여전히 1을 넘겨 튀는지 함께 본다

- [ ] 러너가 실제로 꽂혔는지 확인한다 — `player.TweenRunner`가 `DoTweenRunner`다.
      비어 있으면 폴백이라 겉보기에는 잘 도는 것과 구분되지 않는다

- [ ] **`Time.timeScale = 0`에서 UI 연출이 계속 돈다** (unscaled 인스턴스).
      멈추면 `SetUpdate`가 안 걸렸거나 `Scaled` 인스턴스가 꽂힌 것이다

- [ ] 그래프의 `UseUnscaledTime`을 끄고 다시 `Apply`하면 `timeScale`을 따른다.
      **다시 `Apply`하지 않으면 안 바뀐다** — 이것이 정상 동작이다

- [ ] 연출 중에 오브젝트를 파괴해도 **DOTween 경고가 나오지 않는다.**
      `MotionPlayer.OnDestroy`의 `StopAll`이 `Cancel` → `Kill`까지 닿는지 보는 것이다.
      "Tween is not active" 류의 경고가 뜨면 핸들이 죽은 트윈을 만지고 있다

- [ ] 연출 중에 팝업을 비활성화(`SetActive(false)`)해도 경고가 없고,
      다시 켜면 처음부터 정상적으로 돈다

- [ ] **에디터 프리뷰가 여전히 동작한다** (내장 러너로 폴백).
      플레이 모드가 아닐 때 그래프 창의 프리뷰가 끝까지 돌고 멈춰야 한다.
      **프리뷰가 시작만 하고 끝나지 않으면 DOTween 핸들이 프리뷰에 걸린 것이다.**
      이것이 이 어댑터에서 가장 눈에 띄지 않는 실패 모양이다

- [ ] 씬을 바꿔도 트윈이 남지 않는다. 씬 전환 뒤 `DOTween.PlayingTweens()`가
      이전 씬의 UI 트윈을 들고 있으면 안 된다

- [ ] **원상 복구가 여전히 동작한다** — `Start` 연출 도중에 팝업을 닫으면 대상이
      원래 값(알파·스케일·위치)으로 돌아온다. 중간 값에서 굳어 있으면
      `Cancel`이 `Kill(true)`처럼 마지막 값을 한 번 더 적용한 것이다

- [ ] **`PlayOnEnable`이 켜진 프리팹에서 첫 연출도 DOTween으로 돈다.**
      `MotionDoTweenScope`의 `[DefaultExecutionOrder(-100)]`이 듣는지 보는 것이다.
      첫 연출만 내장 러너로 돌아도 겉으로는 똑같아 보이므로,
      `Start` 발사 직후 `player.TweenRunner`의 타입을 로그로 찍어 확인한다

- [ ] **같은 그래프를 쓰는 플레이어를 여러 개(20개 이상) 동시에 여닫는다.**
      DOTween은 끝난 트윈을 풀로 돌려보내고 재사용한다. 핸들이 재사용된
      인스턴스를 붙잡고 있으면 **연출 하나가 끝나지 않고 멈춰 서거나, 남의 연출이
      중간에 끊긴다.** 20번쯤 연타해도 멈춰 있는 것이 없어야 한다

- [ ] 지속시간 0인 노드가 즉시 끝난다. 한 프레임 늦거나 아예 끝나지 않으면
      러너의 `duration <= 0` 처리가 빠진 것이다

- [ ] `Delay` 노드(진행률을 쓰지 않는 노드)가 제 시간만큼 기다린다

- [ ] 프로파일러로 발사당 할당을 내장 러너와 비교한다. **차이가 없거나 미미하면
      이 백엔드를 켤 이유가 없다** — README의 "언제 이것을 쓰는가"를 다시 읽는다
